1. The 30-Second Elevator Pitch

"Most generative AI tools suffer from two critical flaws: hallucinations and black-box opacity. In high-stakes domains, an AI cannot simply guess—it must prove every statement.

Our platform solves this with an Agentic Corrective RAG (CRAG) engine powered by LangGraph and FastAPI, paired with an editorial React presentation layer. Unlike naive RAG systems that blindly trust whatever chunks they retrieve, our system acts as a quality gatekeeper: it evaluates retrieved evidence in parallel, filters irrelevant noise, triggers live web verification if internal knowledge is incomplete, and streams a live execution trace to the user with exact document and page-level citations."

3. Core Architectural Choices ("Why This, Why Not That?")

Decision What We Chose What We Rejected Winning Rationale for Judges
Backend Layer FastAPI (Python) Pure Node.js / Express The entire AI ecosystem (LangGraph, ChromaDB, PyMuPDF, ONNX) runs natively in Python. Running Python child-processes in Node adds IPC latency. FastAPI provides asynchronous ASGI streaming for Server-Sent Events out-of-the-box.
Frontend Layer React + Vite + Tailwind Streamlit / Gradio Streamlit/Gradio look like internal research demos. React allows custom responsive design tokens, live visual step-tracing, persistent layouts, and production-grade software presentation.
RAG Algorithm Corrective RAG (CRAG) Naive / Vanilla RAG Naive RAG blindly injects top-k chunks into the prompt, risking hallucinations when chunks are noisy. CRAG grades chunks first and triggers query rewriting and web search if documents lack coverage.
Embedding Model Local ONNX MiniLM OpenAI text-embedding-3 Runs locally on CPU in milliseconds with $0.00 API costs, 100% offline capability, and zero external data transmission (air-gapped privacy).
Streaming Method Server-Sent Events (SSE) WebSockets / Polling WebSockets require complex duplex connection state. Polling wastes requests. SSE runs over standard HTTP, auto-reconnects, and streams text & step events natively.
Judge Experience 1-Click Judge Mode Mandatory User Signup Judges only have 3-5 minutes. Forcing account creation or email verification kills demos. Judge Mode bypasses external dependencies with guaranteed uptime.

4. High-Impact AI Vocabulary (Memorize for Presentation)

1. Hallucination Mitigation

Constraining generative output strictly to verified context chunks using negative prompt boundaries ("Do not extrapolate beyond provided text").

2. Corrective RAG (CRAG)

An agentic retrieval architecture that incorporates an active evaluator node to self-correct retrieval gaps prior to answer synthesis.

3. Dual-Model Architecture

Partitioning tasks: a sub-second lightweight model (20B) handles parallel document grading, while a 70B/120B model performs final constrained reasoning.

4. Grounded Provenance & Attribution

Attaching explicit document filenames and page numbers to claims, establishing an immutable audit trail for evaluators.

5. StateGraph Orchestration

Modeling cognitive agent flows as cyclical, state-preserving directed graphs (via LangGraph) with conditional branching and self-healing edges.

6. Normalized Cosine Vector Distance

Measuring angular difference between embedding vectors, ensuring chunk length does not disproportionately bias retrieval relevance.

7. The 5 Hardest Judge Questions & Winning Answers

Q1: "Why shouldn't we just upload these PDFs to ChatGPT / NotebookLM?"
"Consumer tools lack enterprise data privacy, deterministic API integration, and verifiable provenance. Our solution runs local ONNX embeddings where sensitive data never leaves the premises, validates chunk relevance through a dual-model gatekeeper, and integrates into business pipelines via REST/SSE."
Q2: "What happens if ChromaDB retrieves completely irrelevant chunks?"
"That is the exact problem CRAG solves. Naive RAG passes bad chunks to the LLM and hallucinates. Our LangGraph pipeline has an active evaluator node. If less than 50% of chunks are relevant, it rejects the context, rewrites the query, and searches live web sources to self-correct."
Q3: "Why did you use ONNX MiniLM instead of OpenAI embeddings?"
"Three critical advantages: zero API cost, sub-millisecond local latency, and air-gapped privacy. Internal problem documents are processed entirely in-memory on CPU without transmitting sensitive data to third-party endpoints."
Q4: "How does the system handle high query concurrency during peak load?"
"Our grading node executes parallel batch inference using a lightweight model (Groq 20B), completing chunk evaluations in under 700ms. The FastAPI layer is fully asynchronous (ASGI), allowing hundreds of concurrent SSE streams without thread starvation."
Q5: "How does your architecture scale if we add 10,000 documents?"
"ChromaDB uses HNSW (Hierarchical Navigable Small World) index graphs with logarithmic search complexity O(log N). Because our LangGraph pipeline is decoupled, we can seamlessly point the retriever to enterprise vector engines like Milvus or Pinecone with zero changes to agent logic."
